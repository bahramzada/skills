# Orchestration

## Start with the contract

Read the current user request and bundled brief. Record output destination, research/as-of dates, browsing availability, requested scope and any stated resource limit. Ask only about a material blocker; otherwise proceed with stated assumptions. Keep working notes inside the authorized task output area. Do not create a research workspace inside an unrelated software repository.

Maintain a compact task-local ledger with four logical parts: entities, claims, sources and gaps. A Markdown table or in-memory records are sufficient; create sidecar files only if the task needs them. This is evidence tracking, not permission to save the conversation or establish persistent memory.

Map the report:

| Phase | Output sections | Dependency |
|---|---|---|
| Source baseline and taxonomy | 02, official portion of 03 | Current legal and authority records |
| Broad inventory | 03 | Canonical entity identity |
| Profiles and routes | 04–05 | Inventory IDs and practical sources |
| Product planning | 06–09 | Actual field availability and visitor scenarios |
| Reconciliation | 10–11 | Claim/source ledger from every packet |
| Review and assembly | 01, 12, final metadata | Evidence and coverage review |

## Delegate bounded packets

Use actual runtime capacity and permissions. A practical first wave separates:

1. Official national-park and state-nature-reserve inventory, designation changes and access distinctions.
2. Other places and regional coverage, with Naxçıvan, Qarabağ and Şərqi Zəngəzur explicitly assigned.
3. Routes and practical access: endpoints, transport, seasons, permits, geometry provenance and unknowns.

Split or combine packets according to capacity. Profile selected places after the initial inventory. Start product planning once sample records reveal real data availability. Source verification and report composition are dependent work, not interchangeable parallel tasks.

Give each worker only its packet, relevant role references, shared evidence contract, existing canonical IDs and permitted tools/output area. Require:

- Actual search queries and pages opened, with success/partial/failed status.
- Provisional entities, facts with evidence, contradictions and missing fields.
- Clear distinction between a direct statement, an inference and an editorial proposal.
- Remaining work and explicit coverage limits.

Workers return records; the coordinator owns the canonical ledger and final report. Do not allow simultaneous writes to the same report, registry or entity ID map. Worker source labels such as `W1-S001` are temporary. The coordinator canonicalizes URLs/evidence lineages and assigns unique global S001-style IDs after merging. Apply the resulting map to every citation.

## Integrate in dependency order

1. Resolve identity, aliases, category and geography. Reconcile duplicate records before expanding profiles.
2. Merge sources by document identity; retain distinct editions, effective dates and contradictory statements.
3. Check current practical facts separately from historical designation facts.
4. Select profiles for category/region diversity and usable evidence, explaining gaps.
5. Define product features from available records, with unknown-data behavior.
6. Apply editorial MVP criteria, without inventing user demand or quantitative reach.
7. Run quality review. Use a fresh reviewer when the runtime permits it; otherwise run the checklist sequentially and disclose that limitation.

The coordinator owns the final integration and checks important claims against their actual pages. Another agent's confidence label is not independent factual confirmation.

## Budget and stopping

Honor user-specified time, token or cost limits. Otherwise start with targeted official searches, reuse already opened pages and expand only for named coverage gaps. For a failed or unproductive query, try at most two meaningful reformulations before recording the gap and moving on. Respect a provider's retry timing. A single newer authoritative source can be enough; do not chase arbitrary source-count quotas.

The initial review may trigger one targeted repair pass. If a material issue remains, perform one further focused repair only where necessary; then explicitly leave the issue unresolved. Do not restart all completed research. Finish when the requested sections have evidence-backed content or explicit gaps, or the user's limit is reached. Report partial completion when appropriate. No background loops or automatic future sessions.

## Independent AI runs

The bundled brief expects reports from different AI systems to be compared later. Internal specialist workers do not constitute those independent reports. A research run uses only its own evidence and supplied project context; do not import another AI's conclusions unless the user requests comparison. See [comparison](compare-reports.md) for that separate mode.
