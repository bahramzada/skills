# Report contract

The user's requested structure, language, fields, metadata and deliverable take precedence. Do not force a universal report outline onto a narrow question, domain-specific brief or comparison task.

When no format is given, a substantial research report can use:

1. Executive answer and scope.
2. Main findings, grouped by the user's questions.
3. Evidence, comparisons and meaningful contradictions.
4. Practical implications or recommendations, if requested.
5. Limitations, missing evidence and unresolved questions.
6. Source registry with concrete links and supported information.

For durable work, record the research date, relevant as-of period, actual browsing level and completion status. Include AI/model identity only when requested or materially relevant, and never guess an unknown model. Use the user's language. Label estimates, inferences and editorial proposals.

Use stable entity and source IDs where they improve cross-references. Prefer tables for comparable records; split very wide tables by topic. Source links should resolve to the specific document/page, with publication/effective/retrieval distinctions. If offline excerpts were supplied, state their provenance and that original pages were not opened.

Cover the questions to the degree supported by evidence. A count target is not permission to pad a list. Report actual unique counts when relevant. If output limits require parts, preserve user headings/IDs and explicitly state what each part contains and what remains.

Default durable output, if appropriate: UTF-8 Markdown `research-report-<topic>.md` in an authorized directory. Preserve existing files by using a clear revision name. Extra formats, charts, implementation artifacts or external publication require their own task justification/authorization.
